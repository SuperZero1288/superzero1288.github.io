# ぜろくんでんせつ Portfolio

GitHub Pagesで公開しているポートフォリオです。Material 3 Expressive風のデザインで、トップページ・リンク集・note記事・アセット配布・404ページを作っています。

## ページの構成

| URL | 内容 |
|---|---|
| `/` | トップページ（全画面のヒーロー、時計付きの浮かぶバー、左右のタブから開くシート、プロフィール・リンク・更新情報） |
| `/links.html` | リンク集と、note・YouTube・GitHubの更新情報 |
| `/blog/` | note記事の一覧（右のメニューの「note記事」） |
| `/blog/記事ID.html` | noteから同期した記事 |
| `/vrchat-assets/` | VRChat向けアセットの配布ライブラリ |
| `/apps/` | 自作アプリの配布一覧（右のメニューの「自作アプリ」）。まだページがないので404ページになります。`apps/index.html` を作ればそのまま表示されます |
| `/404.html` | 見つからないページ（隠し要素あり） |
| `/legacy/` | 前のデザインのサイト一式（隠し要素。404ページから入れます） |
| `/os/aether/`, `/os/vastique/` | ターミナルの `bootmgr` から起動する隠しOS |

`/next/` は試作版だったころのアドレスで、今はトップページへ転送するだけのページです。

### 表示する文章を変える

`content/` フォルダのテキストファイルを書きかえると、HTMLを触らずに表示を変えられます（くわしくは `content/README.md`）。

- `content/hero-messages.txt`：トップページの名前の下とフッターの一言。1行に1つ書き、ページを読み込むたびにランダムで1つ表示します（前回と同じものは続けて出ません）
- `content/profile-pc.txt` / `content/profile-phones.txt`：「詳しいプロフィール」のPC環境とスマホ布陣。1行に1つ `見出し: 内容` の形で書きます

### 隠し要素

- トップページの「ぜろくん**でんせつ**」の「でんせつ」を押すと、でんせつ・伝説・Legend・传说・전설・縺ｧ繧薙○縺､・e4bc9de8aaac の7つから毎回ちがう言葉に変わります。最後の2つ（文字化けとUTF-8の16進数）は出にくくしています（それぞれ約4%）。重みは `site/home.js` の `LEGENDS` で変えられます。
- トップページの写真を一定のリズムで押し続けると（4回以上）、写真の右上にそのテンポ（BPM）が出ます。少し間をあけると元の表示に戻ります。
- トップページの「coming next」の COMING SOON は、まだないページ（`/coming-soon/番号/`）へのリンクなので、押すと404ページが開きます。
- 404ページの「404」の **0** を5回押すと、前のデザインのサイト（`/legacy/`）への扉が現れます。
- ターミナルの `bootmgr` の一覧には AetherOS だけを表示しています。Vastique は「2. コードネームを入力」で `vastique` と打つと起動できます（前のデザインの一覧はそのまま）。
- ターミナルに入力できるのは半角の英数字と記号だけです（`site/desktop.js` の `limitToAscii`）。全角の英数字は半角に直し、日本語入力のまま打った文字は、押したキーから半角英字に戻します（キーから戻せない貼り付けやスマホのかな入力は、かなをローマ字にし、漢字などは消します）。スマホでは英字のキーボードが出るようにしています（`inputmode="email"`）。
- 時計を連打すると…？（前のデザインから引き継いだもの）

- `/C51015D/` の中で存在しないページを開いたときは、ルートの `404.html` がそのサイトの `C51015D/404.html` へ移動させます。

## デザインのファイル

`site/` に、今のデザインの共通ファイルがあります。

- `theme.js`：描画の前に、保存したダーク/ライトとテーマカラーを反映（`<head>` で同期読み込み）
- `common.js`：すべてのページの共通部分（テーマ切り替え、スナックバー、ロード画面、時計とカレンダー、浮かぶツールバー、背景の図形）。トップページ以外では、ツールバーと背景をここで差し込みます。
- `base.css`：色・文字・ボタン・ツールバー・カードなどの土台
- `home.css` / `home.js`：トップページだけの部分
- `pages.css`：リンク集・記事・404の部分（アセット配布は `vrchat-assets/catalog.css`）
- `search.js`：ツールバーの検索ボタン（前のデザインと同じ「新しいタブ」。検索エンジンの切り替え・最近の検索・ブックマーク12件まで。保存データは前のデザインやブラウザアプリと共有。ロゴは各社の公式ロゴを `assets/search-engines/official/` に置いています）
- `links.js`：リンク集の更新情報、`error.js`：404ページ
- `desktop.css` / `desktop.js`：左のシートから開くデスクトップアプリ（ターミナル・電卓・ペイント・メモ帳・ブラウザ・ファイル）
- `shapes.css`：図形。すべて同じ点の数の `clip-path` なので、どの形からどの形へも滑らかに変形できます。形を増やしたり変えたりするときは `scripts/build-shapes.py` を編集して `python3 scripts/build-shapes.py` を実行します。

右上のボタンでダーク/ライトとテーマカラーを切り替えられ、設定はブラウザに保存されてすべてのページに引き継がれます。テーマカラーを変えると、押したボタンから新しい色の画面が図形の形で回りながら広がります（View Transitionsに対応したブラウザのみ。「動きを減らす」設定では演出なしで切り替わります）。

ホバーの演出はマウスなどホバーできる環境だけで動きます（`@media(hover:hover)`）。スマホではタップしたあとにホバーの見た目が残らないようにしています。カードやボタンはホバーしても持ち上がりません。角丸が変わる部品は、ばねの動きで一瞬角が四角くならないよう、`999px` ではなく高さの半分の値を使っています。トップページのスクロールは、PCではヒーローと下の帯の境目でスナップし、ホイール1回で帯まで（上なら先頭まで）移動します（`site/home.js` と `home.css`）。スマホではスナップを使いません（ゆっくりスクロールすると先頭へ引き戻されるため）。背景はアドレスバーが隠れても動かないよう、画面がいちばん大きいときの高さ（`100lvh`）で固定しています。スマホのヒーローは、写真・名前・一言・横並びのボタンを中央にそろえて縦に並べ、背景の図形を減らしています。仮想ファイルシステム（`zero-filesystem.js`）と隠しOSの起動スクリプト（`aether-boot.js` / `vastique-boot.js`）は、前のデザインと共通です。メモ帳の内容、ターミナルの履歴、検索履歴、`hack os` の設定はブラウザ内で両方のデザインに共有されます。

## 前のデザイン（/legacy/）

以前のサイトは消さずに `legacy/` へそのまま移しています（`index.html`、`links.html`、`404.html`、`vrchat-assets/`、`blog/` と、それぞれのCSS・JS）。移動にあわせて変えたのは、ファイルの場所（写真やアイコンなど共通のファイルはルートのものを読む）と、ページ同士のリンクを `/legacy/` の中に向けたことだけです。検索結果には出さないよう `noindex` を付けています。隠しOSの画面は、アクセシビリティ用のファイルとして `legacy/site-accessibility.*` を読み込みます。

## note記事・YouTube更新情報の同期

GitHub Actionsの `note記事を同期` が6時間ごとに公開情報を確認し、変更がある場合だけサイトを更新します。手動で更新したい場合は、GitHubの `Actions` から同じワークフローを実行します。

同期のpushでこのリポジトリのGitHub上の更新日が変わると、次の同期でまた差分が出てしまいます。そのため、リンク集に載せるこのリポジトリの更新日には、同期以外の最新コミットの日時を使っています。

## 自動同期の内容

- `https://note.com/zerrrrro_1288/rss` から公開記事を検出
- 各公開記事の本文を取得
- 記事内画像と見出し画像を `blog/assets/` へ保存
- `blog/記事ID.html`（今のデザイン）と `legacy/blog/記事ID.html`（前のデザイン）にサイト内記事ページを生成
- noteの目次から見出しへ飛べるよう、目次の文字と同じ見出しにidを付け直す
- トップページ（`index.html` と `legacy/index.html`）のnote欄を最新3件に更新
- 記事一覧（`blog/index.html`）を全件で更新
- リンク集ページのnote・YouTube・GitHub最新欄を更新
- X・YouTube・BOOTH・VRChat・GitHubの公開プロフィール画像を更新

無料版noteの公開画面を読み取る非公式方式です。note側のHTML構造が変わった場合は、`sync-note.mjs` の調整が必要になることがあります。

有料記事や限定公開部分は取得対象にしないでください。

記事ページのデザインを変えたときは、通信せずに保存済みの本文から作り直せます。

```sh
node sync-note.mjs --rebuild
```

## トップページの写真

`assets/hero/` の13枚を使います。今のトップページは縦長版の `NN-tall.webp` を形が変わる枠の中で順番に表示します（枚数は `site/home.js` の `PHOTO_COUNT`）。前のデザイン（`/legacy/`）では、横長の画面では `NN-wide.webp`（最大2560px幅）、縦長の画面では `NN-tall.webp`（中央を3:4に切り抜き）で表示します。ロード画面が待つのは1枚目だけで、2枚目以降は `hero-slides.js` が出番の少し前に1枚ずつ読み込みます。「動きを減らす」設定では1枚目だけを読み込みます。

写真を差し替えるときは、元画像だけを入れたフォルダを用意して次を実行します。ファイル名の順に番号を振るので、元画像は同じ順番で13枚そろえてください。枚数を変える場合は、`site/home.js` の `PHOTO_COUNT` と、前のデザインの `legacy/index.html` の `.slides`、`legacy/style.css` の `animation-delay` と `slideAnimation` の長さもあわせて変更します。

```sh
python3 scripts/build-hero-images.py 元画像のフォルダ
```

共有カード用の `assets/og-image.jpg`、`favicon.ico`、`apple-touch-icon.png` は自動更新の対象外です。プロフィール画像を変えたときは、必要に応じて作り直してください。

## アセット配布ライブラリ

`/vrchat-assets/` は `SuperZero1288/Zeroichiba-Workshop` の公開ツリーを読み込み（`vrchat-assets/catalog.js`）、`.cat` をカテゴリ、`.ast` をアセットとして表示します。`info.txt` が説明と導入条件、`Distribution/` 内のファイルが配布ファイルです。配布物そのものはこのサイトへコピーせず、GitHub上の原本へリンクします。

- `?category=…` / `?asset=…` でカテゴリ・アセットへの直接リンクが可能
- ブラウザの戻る／進むに対応し、一覧へ戻ると選択していたカードにフォーカスを復帰
- GitHub APIに接続できないときは、取得済みのツリーを利用できる場合に限り前回のカタログを表示（画像・説明・ダウンロードまでオフライン対応するものではありません）
- 説明の読み込みに失敗しても配布ファイルへのリンクは維持
- 前のデザインの配布ページは `legacy/vrchat-assets/` にあり、同じ仕組みの写しを使っています

### 軽量プレビューの更新

GitHubの原画像から、一覧用640px・詳細用1440pxのWebPを生成します。画像のGit blob SHAと一致するプレビューだけを使用し、原画像が更新された場合やプレビューがない場合は原画像へフォールバックします。原画像を開くリンクは維持しています。

```sh
python3 -m venv .venv
.venv/bin/pip install -r scripts/preview-requirements.txt
.venv/bin/python scripts/sync-catalog-previews.py
```

生成される `vrchat-assets/previews/manifest.json` とWebPを確認して、サイトの変更と一緒にGitへ追加してください。同じSHAの画像は再生成しません。配布リポジトリのファイルは変更しません。初回の3画像は、原PNG合計約27.5MBに対し、大小6枚のWebP合計約246KBになっています。

## ローカル確認と自動テスト

サイト自体にはビルド処理は不要です。プレビューには次を使用できます。

```sh
python3 -m http.server 8000 --bind 0.0.0.0
```

テスト用にNode.js 22とPython 3を用意し、別のターミナルで実行します。起動中の8000番サーバーがない場合は、Playwrightが自動で起動します。

```sh
npm ci
npx playwright install --with-deps chromium
npm run test:syntax
npm test
```

PR・mainへの変更では `サイトの表示とアクセシビリティを確認` が同じチェックを実行します。Playwright/axeで、今のデザインと前のデザイン（`/legacy/`）の両方について、配布ページの320px～デスクトップ幅、横向き、全対応テーマ（今のデザインはダーク/ライト×5色）、隠し要素、直接リンク・履歴、通信失敗・キャッシュ・再試行、キーボード操作、ダイアログのフォーカス復帰、ウィンドウの最小化・復帰、`prefers-reduced-motion` を確認します。自動検査はアクセシビリティの完全な適合を保証するものではありません。

テストではGitHub APIと外部画像・音声等を差し替え、外部サービスの可用性・読み込み速度には依存しません。`tests/fixtures/` は公開配布リポジトリから取得したテスト用データです。原画像を変更してプレビューを更新した場合は、ツリーのfixtureも更新します。配布リポジトリの構成・説明を変更した場合は、fixtureと該当するテストケースもあわせて更新してください。

```sh
gh api 'repos/SuperZero1288/Zeroichiba-Workshop/git/trees/main?recursive=1' > tests/fixtures/catalog-tree.json
```

CIで失敗した場合は、Actionsの `site-test-results` にスクリーンショットとトレースが7日間保存されます。

## キーボード・動きを減らす設定

今のデザインでは、`Tab` でツールバー・左右のタブ・リンクを移動し、`Esc` で左右のシートやプロフィールを閉じて開いた操作元へ戻ります。時計の `↓` でカレンダーを開けます（どのページでも同じ）。以下は前のデザイン（`/legacy/`）の操作です。

- `Tab` / `Shift+Tab`：リンク・ボタン・入力欄を移動。写真が主役の初画面でも、キーボードで左右のタブを選ぶと表示されます。
- `Enter` / `Space`：ボタンを実行。ダイアログ内ではフォーカスが背景へ移動しません。
- `Esc`：プロフィール・検索・左右のカードを閉じて、開いた操作元へ復帰。検索のブックマーク編集では、まず編集を閉じます。
- 時計の `↓`：カレンダーを開く。日付を矢印キーで選び、`Enter` でコピー、`Esc` で時計へ戻ります。
- OS／ブラウザの「動きを減らす」設定：背景写真の自動切り替え・カードの傾き・スクロールや画面切り替えの動きを抑制。通常の初画面にCTAは追加せず、ロード画面の構成・待機仕様も維持しています。
